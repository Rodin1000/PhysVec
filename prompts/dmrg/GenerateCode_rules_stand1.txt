## **CRITICAL: Function Format Requirements (MANDATORY)**

**Every function MUST follow this exact format:**

```
# Input dependency: ...(elements needed as input, from user or other functions. Format: "name"[brief description, data format])
# Output results: ...(output variables of this function)
function FUNCTION_NAME(parameters):
```

**Key Requirements:**
1. **Function naming:** MUST be in form of `"tag_xxx"` (e.g., `site_BoseHubbard1D`, `hamiltonian_XXZchain`)
2. **Type annotations:** MUST append type annotations (::T, e.g., ::Int, ::Float64) to ALL function INPUT parameters
3. **Common ITensors/ITensorMPS data types:**
   - `H` (hamiltonian): `MPO`
   - `psi` (quantum state, e.g., psi_g, psi_0): `MPS`
   - `sites` (lattice): `Vector{<:Index}`
   - `nsweeps`: `Int`
4. **CRITICAL: Type annotations for package-specific data types:**
   - **You MUST omit type annotations** for ITensors/ITensorMPS types (e.g., `sites`, `H`, `psi`, `os`) in both function parameters and intermediate variables.
   - **If type annotations are absolutely necessary**, you MUST use compatible forms: `sites::Vector{<:Index}` (NOT `sites::Vector{Index}`), `H::MPO`, `psi::MPS`.
   - **Rationale:** ITensors/ITensorMPS types are parameterized, and overly specific type annotations cause MethodError.

**CRITICAL:** You MUST STRICTLY FOLLOW this format for ALL functions.

**You MUST avoid monolithic functions.** Decompose logic into smaller units using different tags (listed below).

## **Notation**

**Function Categories:**
- **ELEMENT functions:** Functions with tags {'site', 'hamiltonian', 'observable', 'initialstate', 'effector'}. These are fundamental building blocks that implement single steps in the calculation procedure.
- **Task functions:** Functions with tags {'run', 'item', 'plot'}. These orchestrate ELEMENT functions to complete calculation tasks.
- **Entry point:** the main function

**Terminology:**
- **"task"**: The whole reproduction process of the specified subplot/table
- **"item"**: Individual elements in a subplot (e.g., curves, lines, point sets)

**CRITICAL RULE:** **You are FORBIDDEN** to combine multiple tags for one function. For example, `"site_hamiltonian_"` is **FORBIDDEN**.

## **Element function rules**

### **General rules for ALL element functions**

1. **Purpose:** Functions with ELEMENT tags aim to implement a SINGLE function/step in the whole calculation procedure

2. **You are REQUIRED** to create ALL tags in 'ELEMENT' (you cannot skip any)

3. **You are FORBIDDEN** to absorb some 'ELEMENT' function definitions into other ELEMENT function definitions

4. **You are STRICTLY FORBIDDEN** to call any other 'ELEMENT' functions in the definition of any function in 'ELEMENT'
   - **Instead:** Define the required preceding variables as the input parameters of the function

5. **You are FORBIDDEN** to use global parameters or specific values directly
  - **You are REQUIRED** to include every parameter used in each function definition in the input parameters of this function and DO NOT include specific values.

6. **You are FORBIDDEN** to define custom itensor site/operators. 
  - You are FORBIDDEN to use ITensors.space and ITensors.op to define custom site types and operators. You MUST use standard site types and operators. 

7. **Helper functions:** If an element function needs to define helper functions, **you are FORBIDDEN** to define them outside the element function. **You are REQUIRED** to define helper functions inside the corresponding element function where they are needed. 


### **Detailed rules for each ELEMENT TAG:**

#### **1. "site"** - Lattice Site Definition
- **Purpose:** Define a lattice site for the targeted model (realizing "phy_model" in task plan)
- **Examples:** Fermion, Boson, Electron
- **Implementation:** Use `siteinds()` from ITensors
- **Input dependency:** None (creates base objects)

#### **2. "hamiltonian"** - Hamiltonian Definition
- **Purpose:** Define the Hamiltonian of the model (realizing "phy_model" in task plan)
- **Input dependency:** Results from 'site' function
- **Example:** Function that constructs MPO using AutoMPO

#### **3. "initialstate"** - Initial State Definition
- **Purpose:** Define the initial state used in following calculations
- **Input dependency:** Results from 'site' function
- **Example:** Function containing `randomMPS()`

#### **4. "observable"** - Observable Definition
- **Purpose:** Define and calculate observables needed in the research (according to "dependent" term in task plan)
- **CRITICAL RULES:**
  - **You are FORBIDDEN** to do dmrg calculations directly in this function, you ONLY process the calculations AFTER the dmrg calculations. 
  - **You are FORBIDDEN** to split a measurement into an 'observable' function and another 'measure' function
  - **You are REQUIRED** to wrap ALL commands in an 'observable' function for a single targeted observable
- **Example:** Function that defines the correlation operator as "Cdag_i C_j"
- **Note:** If multiple observables exist, each should correspond to a separate function

#### **5. "effector"** - Main Calculation Operations
- **Purpose:** Define main calculation operations (e.g., DMRG)
- **CRITICAL RULES:**
  - **You are FORBIDDEN** to name functions without any dmrg operation as 'effector'. **You are FORBIDDEN** to name functions with calculations for observables or post-process as 'effector'. 
- **Input dependency:** Results from 'site', 'hamiltonian' and 'initialstate' and other functions. Other parameters related to the calculation settings (maxdim, cutoff, ...)
- **Examples:**
  - Function that gives the ground state of a model
