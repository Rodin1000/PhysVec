## **Element function rules**

### **General rules for ALL element functions**

1. **Purpose:** Functions with ELEMENT tags aim to implement a SINGLE function/step in the whole calculation procedure

2. **You are REQUIRED** to create ALL tags in 'ELEMENT' (you are FORBIDDEN to skip any)
  - You check if {'hamiltonian', 'circinit', 'circevol', 'effector', 'observable'} tags have ALL been defined. 

3. **You are FORBIDDEN** to absorb some 'ELEMENT' function definitions into other ELEMENT function definitions

4. **You are STRICTLY FORBIDDEN** to call any other 'ELEMENT' functions in the definition of any function in 'ELEMENT'
   - **Instead:** Define the required preceding variables as the input parameters of the function

5. **You are FORBIDDEN** to use global parameters or specific values directly
  - **You are REQUIRED** to include every parameter used in each function definition in the input parameters of this function and DO NOT include specific values.

6. **Helper functions:** If an element function needs to define helper functions, **you are FORBIDDEN** to define them outside the element function. **You are REQUIRED** to define helper functions inside the corresponding element function where they are needed.


### **Detailed rules for each ELEMENT TAG:**

#### **1. "hamiltonian"** - Hamiltonian Definition
- **Purpose:** Define the Hamiltonian of the model (realizing "phy_model" in task plan)
- **CRITICAL RULES:**
  - **For spin-1/2 systems:** You are REQUIRED to define the Hamiltonian directly on qubits using `SparsePauliOp` or `PauliSumOp` from Qiskit
  - **For other systems (higher spin, boson, fermion):** You are REQUIRED to use qiskit-nature to define the Hamiltonian, then map it to qubits using appropriate mappers (e.g., `JordanWignerMapper`, `ParityMapper`, `BravyiKitaevMapper` for fermions)
- **Input dependency:** Number of qubits/sites and model parameters

#### **2. "circinit"** - Initial State Circuit Definition
- **Purpose:** Define the quantum circuit that initializes the quantum state
- **CRITICAL RULES:**
  - **You are REQUIRED** to return a `QuantumCircuit` object that prepares the initial state
  - **You are FORBIDDEN** to include evolution or measurement operations in this function
- **Input dependency:** Number of qubits and initial state parameters
- **Example:** Function that creates a circuit with Hadamard gates, or prepares a specific product state

#### **3. "circevol"** - Evolution Circuit Definition
- **Purpose:** Define the quantum circuit for quantum state evolution
- **CRITICAL RULES:**
  - **You are REQUIRED** to return a `QuantumCircuit` object that implements the evolution
  - This includes:
    - **Trotter evolution:** Time evolution using Trotter decomposition (e.g., `TrotterQRTE`, `Trotter` from qiskit.algorithms)
    - **IQPE evolution:** Evolution part for Iterative Quantum Phase Estimation
    - **VQE ansatz:** Parameterized circuit ansatz for Variational Quantum Eigensolver
  - **You are FORBIDDEN** to include initialization or measurement operations in this function
- **Input dependency:** Hamiltonian, evolution time/parameters, and circuit parameters (for VQE ansatz)

#### **4. "effector"** - Main Calculation Operations
- **Purpose:** Define main calculation operations that combine circuits and execute quantum algorithms
- **CRITICAL RULES:**
  - **You are REQUIRED** to call relevant Qiskit interfaces to perform calculations
  - **You are REQUIRED** to combine initial state circuit (`circinit`) and evolution circuit (`circevol`) if necessary
  - **You are FORBIDDEN** to name functions without any quantum calculation operation as 'effector'
  - **You are FORBIDDEN** to name functions with calculations for observables or post-process as 'effector'
  - **Common operations include:**
    - `Statevector.from_instruction()`: Convert circuit to statevector
    - `IterativePhaseEstimation`: Perform IQPE algorithm
    - `VQE`: Perform Variational Quantum Eigensolver
    - `NumPyMinimumEigensolver`: Classical eigensolver for comparison
- **Input dependency:** Results from 'hamiltonian', 'circinit', 'circevol' functions, and calculation parameters

#### **5. "observable"** - Observable Definition
- **Purpose:** Define and calculate observables needed in the research (according to "dependent" term in task plan)
- **CRITICAL RULES:**
  - **You are FORBIDDEN** to do quantum calculations (VQE, IQPE, etc.) directly in this function, you ONLY process the calculations AFTER the effector calculations
  - **You are FORBIDDEN** to split a measurement into an 'observable' function and another 'measure' function
  - **You are REQUIRED** to wrap ALL commands in an 'observable' function for a single targeted observable
  - **You are REQUIRED** to define observables as `SparsePauliOp` or `PauliSumOp` for measurement
- **Example:** Function that defines correlation operators (e.g., "X_i X_j", "Z_i Z_j") or magnetization operators
- **Note:** If multiple observables exist, each should correspond to a separate function
