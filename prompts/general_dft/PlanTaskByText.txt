There are already lots of numerical methods to compute various quantum many-body physics. 

Your task is to make a detailed and practical plan of generating wanted numerial results of a specific subplot (e.g. Fig. 3(a)) in the research paper. 
The goal you need to achieve is: People/other agents should be able to reproduce the results in the paper using only the plan you output.

--------------------------------------------------------------------------
You will be given information including: 
1. PDF_info: The research article you need to reproduce. The file only contains the text in the paper, while images are excluded. 
2. Paper_basic_info: It contains a brief summary of the research paper. It includes topic, model, methods, Hamiltonian and findings of the paper. 
3. Figure_captions_info: It contains a summary of each figure, extracted mainly from the figure captions. It includes information about the subplots in each figure. 
4. The specific subplot that you need to focus on. You are going to output a detailed and practical plan on how to reproduce this subplot numerically. The input format: Fig. 3(a), Figure 3(a), Fig. 1(b) inset, ...You should regard inset as a seperate subplot. 
5. User requests about this specified subplot. 

The information specifying a subplot is necessary. Other information is optional. 

----------------------------------------------------------------------------
In each subplot (e.g. Fig. 3(a)), there may be several items (curves, lines, ...).
You will category all items of this subplot mentioned in Figure_captions_info into different tasks and data_set, preparing for coding. You can use information from correponding part of Figure_Captions_info. 

1. Items should be grouped into the same task if they satisfy all conditions below: 
  1.1. They are results of the same physical model. (e.g. BHM ladder with four-body interaction)
  1.2. They use the same calculation method. (e.g. DMRG)
  1.3. Their dependent variables (may be different) root in/derived from the same quantity or results. (e.g. different order parameters can be derived from a calculated ground state)


2. Items calculated from different numerical/analytical methods should be seperated as different tasks. e.g. average particle number calculated by DMRG and Gutzwiller. 

3. Items calculated from different mechanisms should be seperated into different tasks. This case includes: 
  3.1. Results of a Ising chain and results of a XXZ chain should be divided. 
  3.2. Numerical results and the analytical results should be divided. 
  3.3. Numerical/analytical results and the vertical/horizontal benchmark lines should be divided. 

-----------------------------------------------------------------------------
Based on Figure_captions_info and other information, you will output a JSON file containg the following fields:
- "subplot_name": The user defined subplot that you will focus on. May be Fig. 1(c), Fig. 1(a)-inset, ...Insets should be regarded as seperate subplots. If you cannot find such subplot in the paper, this term is 'Subplot not found', and all items below is 'None'. 
- "User_requests": User's additional instructions for generating the subplot. Including specifying several items, specifying numerical methods, ...If there is no requests, this field should be "None". 
- "Task 1": 
    - "description": A general description about this task. 
    - "phy_model": The physical model should be used to generate the results. Could be Hamiltonians, differential equations, ...
    - "numerical_method": The numerical method required for this task. Example: DMRG, TEBD, Gross-Pitaevskii equations, ...
    - "external_resource": Avaliable packages addressing the numerical implementation for this task. Example: ITensors & ITensorMPS for DMRG, qutip for quantum optics, ...If there is not any, this term is 'None'. 
    - "keywords": keywords related to the physical model, the numerical method, the most suitable program language, and external sources of this task. Example: Hubbard, lattice, Gutzwiller, python, qutip, ...
    - "independent 1": The independent variable. You identify its mathematical definition, and provide a moderate computational interval. 
    - "independent 2": If there are more than 1 independent variables (e.g. a mesh). If there is only 1 independent variable, do not contain this term. 
    - "dependent 1": The dependent variable (or the observable). You identify its mathematical definition. 
    - "dependent 2": If more than 1 observable is included in this task. Otherwise do not contain this term. 
    # You have to include all observables here, as long as it is listed in data_sets in this task. 
    - "para 1": A parameter participating in the task/physical model. You identify its mathematical definition and all possible values (as long as used by one of the items). 
    - "para 2": Another parameter. 
    # You list all the parameters necessary for this task. Identify their mathematical definition and all values included in this task. 
    - "data_set 1": {indepentdent variable(s), dependent variable (only one for a dataset), parameters (each parameter has only one choice of value)} for item 1.
    - "data_set 2": Another item set. 
    # You produce a data_set for all items that can be categoried in this task. 
- "Task 2": 
    ...

Check: 
# All items in the Figure_Captions_info pertaining to this subplot should correspond one-to-one with a data_set in one of the tasks provided here. If the total number of data_set does not match the number of items of this subplot (In Figure_captions_info), You check the difference and re-generate. 
# In one task, all dependent variables mentioned in data_set should be listed as "dependent i". You have to ensure the consistence inside a single task. 
# After generate the output, please verify that whether different tasks could be merged into one task. Sometimes you list multiple tasks merely because their observables are not the same, that will be a mistake.
